B. Input-responsive movement
Use existing React patterns and a small reusable state model:
- IDLE: gentle breathing/body bob and occasional blink; subtle, not distracting.
- POINTER_TRACK: eyes follow pointer within a bounded range; head/upper body subtly follow with smoothing.

- SPEAKING: subtle mouth/face movement if supported; otherwise restrained movement only while actually speaking.
- LISTENING: attentive pose while microphone capture is active.
- THINKING: small considering pose while a request is processing.
- HAPPY/SUCCESS: brief friendly reaction, then return to idle.
- CONFUSED/ERROR: subtle head tilt/concern, not exaggerated comedy.
- SLEEPY: slow blink/soft idle only when explicitly triggered.
- Respect reduced-motion preferences and reduce/pause nonessential animation when page is hidden.
- Clean up listeners, animation frames, observers and timers. Avoid timers multiplying after rerenders.
- Convert pointer position relative to the Buddy container, not whole browser window. Bound movement.
- Avoid React state updates on every pointer pixel; throttle with requestAnimationFrame or use existing motion engine.
